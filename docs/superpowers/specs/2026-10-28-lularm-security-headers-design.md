# Lularm Test Security Headers Design

## Intent

Remediate the three medium-risk items reported by ZAP for the
`www.lularm.com` test environment without disrupting the Nuxt, Wagtail,
Fast-ID, or certificate API flows.

## Scope

- Add an enforced, minimally restrictive CSP at the Nginx edge.
- Add an anti-clickjacking compatibility header.
- Keep Cloudflare Browser Insights enabled, but exclude its third-party host
  from the ZAP application scope.
- Back up the live Nginx configuration and retain a tested rollback path.

## Non-goals

- Do not create a strict script, style, image, or connection allowlist in this
  change; that requires a separate CSP report-only observation period.
- Do not change application code, databases, Fast-ID settings, or API secrets.
- Do not modify the CORS policy of `static.cloudflareinsights.com`, which is
  controlled by Cloudflare rather than the test VM.

## Approaches

1. **Documentation only.** Add the live directives to an operations guide.
   This is small, but Git cannot validate the deployable configuration and a
   future copy/paste can silently drop the headers.
2. **Version the complete test-site configuration (selected).** Store the
   `semi-e187` Nginx site under `deploy/nginx/`, add a structural regression
   test, and document how to install it. This keeps the live routing and the
   security fix reviewable together.
3. **Version only a shared header snippet.** This avoids duplicating the site
   routes, but it does not capture the `add_header` inheritance problem caused
   by the FIDO location and is easier to install incorrectly.

The selected approach is the complete versioned test-site configuration. It
matches the user's need to see the remediation in Git and gives CI a concrete
artifact to validate.

## Approved approach

Set these headers from the HTTPS `server` block using the installed
`headers-more` module:

```nginx
more_set_headers "Content-Security-Policy: frame-ancestors 'self'; object-src 'none'; base-uri 'self';";
more_set_headers "X-Frame-Options: SAMEORIGIN";
```

This CSP blocks cross-origin framing, plugins, and hostile base URL changes
without restricting existing script, style, image, or API origins. Same-origin
framing remains available for Wagtail page and block previews. ZAP should no
longer report the missing CSP or anti-clickjacking headers.

`more_set_headers` is used instead of `add_header` because the existing
`/account/security/` location defines its own cache header. Native Nginx
`add_header` inheritance would otherwise omit the server-level security
headers on that FIDO route.

Treat the CORS alert for `static.cloudflareinsights.com` as third-party and
out of scope. Restrict the ZAP context to `lularm.com` and `www.lularm.com`,
and exclude `static.cloudflareinsights.com` before rescanning. Also exclude
`/cdn-cgi/` responses because those paths are generated by Cloudflare rather
than the application origin.

## Verification

- `nginx -t` succeeds before reload.
- The public home page, English home page, admin page, and account security
  route continue returning expected HTTP responses.
- Public responses contain both security headers with the approved values.
- ZAP rescans only the approved test domains and no longer counts the
  Cloudflare Beacon alert as an application finding.

## Rollback

Restore the timestamped Nginx backup, run `nginx -t`, and reload Nginx. ZAP
scope changes can be reverted by removing the exclusion from the local test
context.

The repository artifact is installed only after copying the existing live
configuration to a timestamped backup. Reverting the Git commit does not by
itself change the running VM.
