# 電子證書清單 API 串接設計

日期：2026-10-27

## 目的

將目前證書管理頁面的 18 筆示範資料改為客戶電子證書 API 的即時資料，同時確保 API Key 僅存在伺服器環境，不會傳送至瀏覽器。

## 已確認範圍

- 客戶 API Base URL：`http://192.168.1.123:8011`
- 上游端點：`GET /api/v1/external/certificates`
- 認證 Header：`X-API-Key`
- 使用 `.env`／正式環境環境檔保存 Base URL 與 API Key。
- 頁面保留既有搜尋、證書狀態篩選、表格與詳細資料區塊。
- 上游未提供的「發證日」與「作業進度」顯示 `-`；作業進度篩選暫時只提供「全部狀態」。

## 實作方式比較

1. **Nuxt 伺服器端代理（採用）**：在 Nuxt Nitro 建立本站 API，由伺服器加入 `X-API-Key` 後呼叫內網 API。改動集中在現有前台專案，瀏覽器不會取得金鑰。
2. **Django 伺服器端代理**：安全性同樣足夠，但需要新增 Django 路由並讓前台跨服務呼叫，對僅供此 Nuxt 頁面使用的清單而言改動較多。
3. **瀏覽器直接呼叫客戶 API（不採用）**：會向瀏覽器暴露 API Key，且受到 CORS 與內網可達性限制。

## 設定

Nuxt 私有 runtime config 從下列環境變數讀取：

- `ESIGN_API_BASE_URL`
- `ESIGN_API_KEY`

API Key 不可放入 `runtimeConfig.public`、前端 JavaScript、Git 或錯誤訊息。

## 資料轉換

| 上游欄位           | 頁面欄位           |
| ------------------ | ------------------ |
| `certificateNo`    | 證書號碼           |
| `currentVersionNo` | 目前版本           |
| 無                 | 發證日，顯示 `-`   |
| `expiresAt`        | 到期日             |
| `status`           | 證書狀態           |
| 無                 | 作業進度，顯示 `-` |

狀態支援 `PENDING`、`VALID`、`SUSPENDED`、`REVOKED`，並在中英文介面提供對應文字。

## 錯誤處理

- 缺少伺服器環境設定時，本站 API 回傳通用設定錯誤，不揭露金鑰。
- 上游逾時、網路錯誤、非成功 HTTP 或格式錯誤時，本站 API 回傳通用服務錯誤。
- 前台顯示可理解的載入失敗訊息與重試按鈕，不退回示範資料，避免把假資料誤認為正式資料。
- 清單為空時沿用既有空結果畫面。

## 測試

- 單元測試資料格式驗證、狀態轉換與篩選。
- 伺服器端測試確認請求使用正確 URL 與 `X-API-Key`，並覆蓋缺少設定及上游錯誤。
- 前台型別檢查、測試與正式建置必須通過。

## 非本階段範圍

- 證書建立、修改、撤銷或下載。
- 發證日與作業進度的推導或額外 API 串接。
- API 分頁；目前規格定義回傳完整陣列。
