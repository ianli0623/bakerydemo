# Trivy 套件漏洞修正與本機重新打包

範圍：修正 2026-11-03 部署包掃描的套件漏洞，在隔離工作目錄完成測試並產生新部署包；不部署、不推送、不變更主機設定。

## 基準

- 來源：`f7e17da93c41d0b20dbca46a7019e9a19a43e618`。
- Trivy 0.76.1，啟用開發相依套件掃描：93 筆，Critical 3、High 39、Medium 36、Low 15。
- 告警均來自 Nuxt 的 npm 鎖定檔，部分套件亦存在於已編譯的 SSR 執行期。
- 不透過忽略告警或移除鎖定檔處理。
- 擴大來源掃描另找到根目錄開發工具的 31 筆告警，亦在本次更新中處理；未修改 UI 或認證流程。

## 執行步驟

1. 升級 Nuxt 與 Vue 至已修補版本，重新解析相容的間接相依套件。
2. 使用獨立的 Node.js 24.22.2，保持系統既有 Node.js 不變；同步標明最低版本需求。
3. 執行 Trivy 複掃，追蹤剩餘告警的相依來源，僅在確認相容性後調整版本限制。
4. 執行前台單元、型別、正式建置、CSP 整合及開發伺服器測試，並執行 Django 與格式檢查。
5. 進行獨立審查，處理重要問題，保留實際測試與掃描紀錄。
6. 從已驗證的來源與新建置產物產生新部署資料夾、壓縮檔及 SHA-256 校驗；確認未包含真實環境檔、金鑰、資料庫或媒體。
7. 掃描完整部署資料夾，確認來源與產物的漏洞結果，記錄未能解決的限制（若有）。

## 驗收

- 原始 93 筆告警皆有版本修正或明確結果，完整新部署包完成 Trivy 掃描。
- 既有前後台測試通過，維持 CSP、CMS、證書查詢及 Fast-ID 行為。
- 部署包可在本機啟動，檔案校驗通過，清楚列出 Node.js 需求。
